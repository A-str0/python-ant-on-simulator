# ПЛАН ТЕСТИРОВАНИЯ SPRINT 3: TUI, Графики и Полный Аннигиляционный Пиздец

## 1. Обзор новых фичей Sprint 3

Sprint 3 вводит три крупных раздела функционала:

1. **TUI-интерфейс** — переход с говноконсоли на полноценный терминальный интерфейс
2. **Графики и визуализация** — ASCII-графики популяции, еды, радарные диаграммы, тепловые карты
3. **Новые механики** — экономика ресурсов, крипто-муравьиные биржи, войны, новые комнаты, статусы, события

## 2. Тестирование TUI-интерфейса (Terminal User Interface)

### 2.1 Базовая функциональность TUI

#### T2.1.1 - Инициализация и запуск TUI
- **Требование**: TUI-приложение стартует без ошибок
- **Входные данные**: Запуск программы с флагом `--tui`
- **Ожидаемый результат**: 
  - Экран затирается и вся колония отображается в TUI
  - Видны header, боковые панели, лог событий
  - Нет артефактов, мигания, неправильного переноса текста
- **Критерий успеха**: TUI загружается за < 2 секунды без ошибок

#### T2.1.2 - Ресайз терминала
- **Требование**: При изменении размера терминала интерфейс адаптируется
- **Входные данные**: Во время работы TUI изменить размер окна терминала
- **Ожидаемый результат**: 
  - Все панели переорганизуются, текст не съезжает
  - Графики пересчитываются под новый размер
  - Нет потери данных или крешей
- **Критерий успеха**: Интерфейс остаётся функциональным при любом размере (минимум 80×24)

#### T2.1.3 - Double-buffering без мигания
- **Требование**: Обновление состояния происходит плавно, без мигания экрана
- **Входные данные**: Симуляция работает на скорости 2× или выше
- **Ожидаемый результат**: 
  - Экран обновляется без видимого мигания
  - Нет артефактов от очистки экрана (`os.system('clear')`)
- **Критерий успеха**: Визуальное восприятие - плавное, без технических артефактов

### 2.2 Макет экранов и навигация

#### T2.2.1 - Главный экран (Dashboard)
- **Требование**: Dashboard содержит все необходимые компоненты
- **Компоненты для проверки**:
  - Header: название колонии, вид муравьёв, время, иконка погоды
  - Левая панель: список муравьёв с ID, возраст, комната, статусы
  - Правая панель: график популяции, график еды, распределение по комнатам, радарная диаграмма
  - Лог событий (нижняя панель)
  - Панель управления (самый низ)
- **Ожидаемый результат**: Все компоненты видны и актуальны
- **Критерий успеха**: Информация обновляется в реал-тайме

#### T2.2.2 - Фокус и переключение между панелями (Tab)
- **Требование**: Переключение между панелями работает корректно
- **Входные данные**: 
  - Нажимать `Tab` последовательно
  - Нажимать `Shift+Tab` для обратного движения
- **Ожидаемый результат**: 
  - Активная панель выделяется визуально (цвет рамки, подсветка)
  - Порядок циклический: левая → правая → лог → управление → левая
  - Input фокусируется правильно
- **Критерий успеха**: Навигация интуитивна и не зависает

#### T2.2.3 - Экран комнаты (Enter на комнате в списке)
- **Требование**: Детальный экран комнаты показывает информацию корректно
- **Входные данные**: 
  - Выбрать муравья из списка левой панели
  - Нажать Enter, перейти на его комнату
- **Ожидаемый результат**: 
  - Открывается экран с названием комнаты, типом, вместимостью
  - Список муравьёв в комнате видны с характеристиками Б.И.Л.Ь.Я.Р.Д.
  - Отображается специфичная информация комнаты (склад, кладбище, бильярдная и т.д.)
  - Возможность вернуться на dashboard (ESC или Back)
- **Критерий успеха**: Информация корректна и релевантна типу комнаты

#### T2.2.4 - Полноэкранный режим графиков (g)
- **Требование**: Режим графиков доступен и работает
- **Входные данные**: 
  - В dashboard нажать `g`
  - Переключаться между графиками `←`/`→`
- **Ожидаемый результат**: 
  - Открывается полноэкранный режим с графиком
  - Название графика отображается в заголовке
  - Графики переключаются по циклу: Population → Food → B.I.L.Y.A.R.D. → Heatmap → Death → Billiard Index → Voting
  - Нажатие `g` снова возвращает на dashboard
- **Критерий успеха**: Все 7 графиков доступны и корректны

#### T2.2.5 - Экран сохранений (S)
- **Требование**: Экран управления сохранениями функционален
- **Входные данные**: 
  - Нажать `S` (Shift+S) на dashboard
- **Ожидаемый результат**: 
  - Отображается список сохранений с датой, размером, иконкой
  - Возможность выбрать сохранение и загрузить (Enter)
  - Возможность перезаписать (`Ctrl+S`), удалить (`Delete`), экспортировать в JSON (`E`)
  - Сортировка по дате, размеру, имени
  - Предпросмотр мини-дашборда при фокусе на сохранении
- **Критерий успеха**: Сохранения управляются интуитивно, без потери данных

#### T2.2.6 - God Mode (Ctrl+G + пароль)
- **Требование**: God Mode открывается и работает после пароля
- **Входные данные**: 
  - Нажать `Ctrl+G`
  - Ввести пароль `billiard123`
- **Ожидаемый результат**: 
  - Открывается панель бога с ползунками и кнопками
  - Доступны: изменение еды, погода, влажность, температура, зомби-гриб
  - Кнопки: "Натравить вредителей", "Случайное событие", "Воскресить мёртвых", слайдер дебильности
  - Чекбокс "Режим балагана"
  - Счётчик нажатий (сбрасывается на 1488)
- **Критерий успеха**: God Mode работает, изменения применяются немедленно

### 2.3 Горячие клавиши

#### T2.3.1 - Базовые хоткеи воспроизведения
- **Требование**: Все клавиши управления воспроизведением работают
- **Входные данные**: На dashboard нажать последовательно:
  - `Space` - пауза/продолжить

  - `p` - пауза (альтернатива)
- **Ожидаемый результат**:

  - `→` при паузе делает один тик
  - `p` работает как Space
- **Критерий успеха**: Контроль воспроизведения работает интуитивно

#### T2.3.2 - Хоткеи скорости
- **Требование**: Все уровни скорости доступны
- **Входные данные**: На dashboard нажать `1`, `2`, `3`, `4`, `5`

  - `1` → 1× скорость (нормальная)
  - `2` → 2× скорость
  - `3` → 5× скорость
  - `4` → 10× скорость
  - `5` → MAX скорость (максимально быстро)

#### T2.3.3 - Хоткеи сохранения/загрузки
- **Требование**: Сохранение и загрузка работают из dashboard
- **Входные данные**: 
  - `s` - сохранить текущее состояние
  - `l` - загрузить последнее сохранение
  - `S` - экран сохранений
- **Ожидаемый результат**: 
  - `s` сохраняет состояние, показывает уведомление
  - `l` загружает последнее сохранение и отображает колонию
  - `S` открывает экран управления сохранениями
- **Критерий успеха**: Все операции завершаются успешно

#### T2.3.4 - Хоткеи выхода
- **Требование**: Выход из программы работает с подтверждением и без
- **Входные данные**: 
  - `q` - выход с подтверждением
  - `Q` (Shift) - выход без сохранения
  - `Ctrl+C` - аварийное сохранение и выход

  - `q` показывает диалог "Вы уверены?" → можно отменить
  - `Q` выходит без сохранения (нужно ещё раз подтвердить)
  - `Ctrl+C` сохраняется автоматически и выходит
- **Критерий успеха**: Выход безопасен, данные не теряются при `s`, `l`, `Ctrl+C`

#### T2.3.5 - Хоткеи назначения и голосования
- **Требование**: Функции назначения и голосования доступны по хоткеям

## 3. Тестирование графиков и визуализации (ASCII-CHARTS)

### 3.1 Технические требования графиков

#### T3.1.1 - ASCII/Unicode рендеринг
- **Требование**: Графики рисуются символами, не вызывают matplotlib
- **Входные данные**: Открыть режим графиков (нажать `g`)
- **Ожидаемый результат**: 
  - Видны символы: `▁▂▃▄▅▆▇█`, `░▒▓█`, `│─┌┐└┘├┤┬┴┼`
  - Нет импорта matplotlib, graphviz или других GUI-библиотек
  - Графики строятся из текстовых элементов
- **Критерий успеха**: Графики полностью текстовые

#### T3.1.2 - Адаптация к размеру терминала
- **Требование**: Графики масштабируются под размер окна
- **Входные данные**: 
  - Открыть режим графиков
  - Изменить размер терминала (например, 120×40, потом 60×20)
- **Ожидаемый результат**: 
  - График пересчитывается и остаётся понятным
  - Текст не выходит за границы
  - Пропорции сохраняются или адаптируются адекватно
- **Критерий успеха**: Графики читаемы при любом размере (минимум 60×20)

#### T3.1.3 - Компоненты графика (заголовок, оси, легенда, сетка)
- **Требование**: Все графики имеют необходимые компоненты
- **Входные данные**: Открыть несколько графиков (`g`, затем `→`)
- **Ожидаемый результат**: 
  - Каждый график имеет **заголовок**
  - Видны **подписи осей** (X и Y)
  - Есть **легенда** с расшифровкой линий/цветов
  - Опционально: сетка для удобства чтения
  - **Масштабирование** по Y автоматическое
- **Критерий успеха**: Все компоненты присутствуют и понятны

#### T3.1.4 - История данных (минимум 1000 тиков)
- **Требование**: Графики хранят историю за длительный период
- **Входные данные**: 
  - Запустить симуляцию на скорости MAX
  - Ждать 100+ реальных секунд
  - Открыть граф популяции
- **Ожидаемый результат**: 
  - График показывает данные за минимум 1000 симуляционных тиков (если запущено такое время)
  - История гладкая, без пробелов
  - Память не взрывается (проверить объём памяти процесса)
- **Критерий успеха**: История сохраняется корректно

### 3.2 Список обязательных графиков

#### T3.2.1 - График популяции (Population Chart)
- **Требование**: График показывает динамику популяции
- **Входные данные**: 
  - Симуляция работает несколько тиков
  - Открыть режим графиков (`g`)
  - Первый график должен быть Population
- **Ожидаемый результат**: 
  - Ось X: время (в тиках), ось Y: количество муравьёв
  - **Четыре линии**:
    - Зелёная: живые муравьи
    - Красная: мёртвые муравьи
    - Жёлтая: муравьи в процессе рождения
    - Синяя: всего муравьёв
  - Auto-scale по Y
  - **Маркеры событий**: вертикальные линии с метками для: смерть матки, эпидемия, нападение вредителей
- **Критерий успеха**: Все линии видны, события отмечены

#### T3.2.2 - Пищевая панель (Food Dashboard)
- **Требование**: Показывает запасы и потребление еды
- **Входные данные**: 
  - Открыть режим графиков, переключиться на второй (`→`)
- **Ожидаемый результат**: 
  - **Линейный график**: запас еды во времени (синяя линия)
  - **Гистограмма**: потребление еды по комнатам (разные цвета для каждой комнаты)
  - **Pie chart (ASCII)**: распределение типов еды:
    - Семена
    - Мясо
    - Сироп
    - Грибы
    - Листья
    - Бильярдные чипсы
  - Легенда с расшифровкой процентов
- **Критерий успеха**: Все три представления (график, гистограмма, пирог) работают

#### T3.2.3 - Радар Б.И.Л.Ь.Я.Р.Д. (Stats Radar)
- **Требование**: Семиугольная звезда показывает средние характеристики
- **Входные данные**: 
  - Открыть режим графиков, третий графика (`→→`)
- **Ожидаемый результат**: 
  - **Семиугольная звезда** на 7 осях (Б, И, Л, Ь, Я, Р, Д)
  - На каждой оси — среднее значение характеристики по колонии (0-10)
  - **Основной радар**: толстая линия для колонии в целом
  - **Overlay**: тонкие линии для каждой комнаты (если их 5+ — показывать топ 5)
  - **Дополнительно**: если выбран конкретный муравей — его личный радар поверх колонии (другой цвет)
- **Критерий успеха**: Радар читаем и отражает действительность

#### T3.2.4 - Тепловая карта муравейника (Nest Heatmap)
- **Требование**: 2D ASCII-рендер муравейника с цветовой заливкой
- **Входные данные**: 
  - Открыть режим графиков, четвёртый график
- **Ожидаемый результат**: 
  - **2D вид сверху** на муравейник (комнаты отображены как блоки/ячейки)
  - **Цветовая заливка** в зависимости от выбранного режима (начально — температура):
    - Синий: холодно
    - Зелёный: нормально
    - Красный: жарко
  - **Переключение режима** клавишами:
    - `t` (temp) → температура
    - `h` (humidity) → влажность
    - `d` (density) → плотность муравьёв
    - `p` (poop) → количество говна
    - `s` (satisfaction) → уровень счастья
  - Легенда с диапазоном цветов
- **Критерий успеха**: Все 5 режимов работают, карта понятна

#### T3.2.5 - Смертельный таймлайн (Death Timeline)
- **Требование**: Столбиковая диаграмма смертей по причинам
- **Входные данные**: 
  - Открыть режим графиков, пятый график
  - Пусть произойдут события (смерти)
- **Ожидаемый результат**: 
  - **Столбиковая диаграмма** смертей за последние 100 тиков
  - Ось X: время (тики), ось Y: количество смертей
  - **Цветовое кодирование** причины смерти:
    - Синий: старость
    - Красный: голод
    - Оранжевый: взрыв
    - Пурпурный: зомби
    - Серый: потерян при голосовании
    - Жёлтый: разрыв сердца от бильярда
    - Чёрный: неизвестно (дедлайн)
  - Легенда с расшифровкой
- **Критерий успеха**: Причины смертей отслеживаются и выводятся корректно

#### T3.2.6 - Политический компас (Political Compass)
- **Требование**: 2D scatter plot для муравьёв
- **Входные данные**: 
  - Открыть режим графиков, шестой график
- **Ожидаемый результат**: 
  - **Ось X**: консерватизм (сколько раз "против") ← → либерализм (сколько раз "за")
  - **Ось Y**: авторитарность (близость к матке) ← → анархия (время в бильярдной)
  - Каждая **точка = муравей**
  - **Цвет точки**: статус муравья (живой, мёртвый, зомби и т.д.)
  - **Размер точки**: грузоподъёмность муравья
  - Легенда с расшифровкой статусов
- **Критерий успеха**: Точки распределяются логично

#### T3.2.7 - Корреляционная матрица (Billiard-conomy)
- **Требование**: Таблица корреляций с цветовой индикацией
- **Входные данные**: 
  - Открыть режим графиков, седьмой график
- **Ожидаемый результат**: 
  - **Таблица корреляций** между переменными:
    - Количество бильярдных партий ↔ Продуктивность
    - Бильярдные партии ↔ Счастье
    - Бильярдные партии ↔ Смертность
    - Уровень шума в бильярдной ↔ Моральный дух
    - Курс ANTCOIN ↔ Благосостояние колонии
  - Значения от -1 до 1 (корреляция)
  - **Цветовая индикация**:
    - Красный: отрицательная корреляция (-1)
    - Белый: нет корреляции (0)
    - Зелёный: положительная корреляция (+1)
  - Таблица читаема
- **Критерий успеха**: Корреляции вычисляются и выводятся

### 3.3 Интерактивность графиков

### 4.1 Муравьиная экономика и ресурсы

#### T4.1.1 - Трёхресурсная модель
- **Требование**: Три типа ресурсов работают независимо
- **Входные данные**: 
  - Создать колонию > 50 муравьёв
  - Понаблюдать за складом через несколько тиков
- **Ожидаемый результат**: 
  - Три ресурса видны в инвентаре:
    - **ЛТСУ** (базовая еда)
    - **ПББ** (мясо, насекомые)
    - **СЗУ** (сироп, снеки)
  - Каждый ресурс имеет запас (числовое значение)
  - **Каждый вид муравьёв** имеет разные коэффициенты потребления (проверить в характеристиках колонии)
  - При падении ресурса ниже 10%: появляется предупреждение и начинаются эффекты:
    - Нет ЛТСУ: муравьи голодают (смерти за 5-10 тиков)
    - Нет ПББ: матка перестаёт рожать солдат
    - Нет СЗУ: падает счастье, риск бунта
- **Критерий успеха**: Ресурсы управляются корректно

#### T4.1.2 - Биржа ресурсов (RESOURCE MARKET)
- **Требование**: Рыночная сессия работает каждые 10 тиков
- **Входные данные**: 
  - Запустить симуляцию, дождаться рыночной сессии (каждые 10 тиков)
  - Проверить панель "Биржа" в TUI
- **Ожидаемый результат**: 
  - **Раз в 10 тиков** включается рыночная сессия (событие в логе)
  - Муравьи трейдят ресурсы между комнатами
  - **Курс устанавливается спросом и предложением**:
    - Переизбыток СЗУ → цена падает
    - Голод ЛТСУ → цена взлетает
  - **Спекулянты** (муравьи с высоким Б) скупают в одном месте, перепродают в другом
  - Муравей со статусом `fermented` может совершить невыгодную сделку (50% шанс)
  - Муравей с низким И может проиграть ресурсы в "бильярдные опционы"
  - Курсы выводятся в отдельной панели (или в логе событий)
- **Критерий успеха**: Биржа работает, курсы изменяются

#### T4.1.3 - ANTCOIN майнинг
- **Требование**: Крипто-майнинг работает в Серверной
- **Входные данные**: 
  - Создать колонию > 100 муравьёв (тогда появится Серверная)
  - Назначить несколько муравьёв в Серверную
  - Наблюдать за выработкой ANT
- **Ожидаемый результат**: 
  - **Появляется новая комната "Серверная"** при > 100 муравьёв
  - Каждый майнер:
    - Сжигает 0.5 еды за тик
    - Производит 0.01 ANT
  - Баланс ANT выводится в инвентаре
  - **Использование ANT**:
    - Ускорить рождение муравья
    - Нанять наёмника из соседней колонии
    - Купить буст характеристик
    - Подкупить избирателей на голосовании
  - Рандомное событие "Обвал ANT" может произойти (курс падает на 50%+)
  - **Хардфорк**: если 50%+ проголосуют "за", создаётся ANTCOIN CLASSIC (не сумма не обновляется)
- **Критерий успеха**: Майнинг работает, ANT можно потратить

#### T4.1.4 - Чиновники и коррупция
- **Требование**: Чиновники появляются и крадут ресурсы
- **Входные данные**: 
  - Создать колонию > 50 муравьёв
  - Дождаться автоматического появления чиновников (муравьи с высоким Я)
- **Ожидаемый результат**: 
  - При достижении > 50 муравьёв: автоматически выбираются чиновники (высокий Я)
  - Чиновник берёт **5% ресурсов**, проходящих через его комнату
  - **Максимум чиновников**: 1 на 25 муравьёв (округляется вверх)
  - Чиновник может быть **смещён голосованием** (требуется 66%+)
  - Если не смещён 100 тиков → статус `corrupted`, берёт 10%
  - **Два чиновника** могут создать "комитет" и потратить 20% бюджета на хуйню (событие, видно в логе)
  - Можно проверить статус чиновника: нажать `R` → "Все чиновники" → видны их имена, уровень коррупции
- **Критерий успеха**: Чиновники работают, их можно смещать

    - "Угадай травинку" (50/50)
    - "Бильярд-рулетка" (30/70)
    - "Ставки на голосование"
  - **Выигрыш**: +2 счастье, +3 Д, +ресурсы
  - **Проигрыш**: -1 счастье, -1 Д, потеря ресурсов, 10% получить `billiard_main`
  - **Владельцы** (чиновники): получают 15% от оборота казино
  - В логе: "Муравей X выиграл в казино", "Муравей Y проиграл в казино"
- **Критерий успеха**: Казино работает, муравьи выигрывают/проигрывают

#### T4.4.5 - Комната отдыха с гамаками (Hammock Lounge)
- **Требование**: Комната для отдыха (0 продуктивности, +счастье)
- **Входные данные**: 
  - Создать/найти Hammock Lounge
  - Назначить муравьёв отдыхать
- **Ожидаемый результат**: 
  - Муравьи ничего не делают, лежат в гамаках
  - +5 счастье за тик (до максимума)
  - Продуктивность: 0
  - **Эффект переполнения**:
    - Если 30%+ колонии в гамаках → остальные получают статус `outraged`
    - Если 50%+ → забастовка (голосования блокируются, чиновники теряют власть на 10 тиков)
  - В логе: "Муравьи начали забастовку!"
- **Критерий успеха**: Гамаки работают, забастовка возможна

#### T4.4.6 - Оружейная (Armory)
- **Требование**: Хранилище киёв, переделанных в копья
- **Входные данные**: 
  - Создать/найти Оружейную
  - Запустить войну
- **Ожидаемый результат**: 
  - Хранит бильярдные кии (переделанные в копья)
  - **Каждый кий** +5% к обороне комнаты
  - Максимум: 10 киёв на комнату
  - Кии производятся в бильярдной (1 кий = 5 тиков + 10 еды)
  - Если 0 киёв при войне → оборона -50%
  - В TUI: видно количество киёв
- **Критерий успеха**: Оружейная работает, кии влияют на оборону

#### T4.4.7 - IT-отдел (IT Department)
- **Требование**: Комната для IT-администраторов (высокий Р)
- **Входные данные**: 
  - Создать/найти IT-отдел
  - Назначить муравьёв с высоким Р
- **Ожидаемый результат**: 
  - Муравьи ничего не производят, просто сидят
  - **Бонус**: если "феромоновая сеть сбилась" → чинят за 2 тика (вместо 10)
  - **Требования**: раз в 50 тиков требуют обновить ПО (съедают 20 еды)
  - Если не обновлять → производительность феромоновой навигации -30%
  - В логе: "IT-отдел требует обновления ПО", "ПО обновлено успешно"
- **Критерий успеха**: IT-отдел работает, может ускорить починку

### 4.5 Статусы муравьёв (новые)

#### T4.5.1 - Статус `radiated`
- **Проверка**: Получить через Космический луч событие
- **Эффекты**: +3 к рандомной характеристике, распространяет радиацию на соседей
- **Снять**: Время (50 тиков) или изоляция в отдельной комнате

#### T4.5.2 - Статус `abducted`
- **Проверка**: Получить через НЛО событие
- **Эффекты**: Муравей исчезает из колонии
- **Снять**: Автоматически через 50 тиков (3/5 возвращаются)

#### T4.5.3 - Статус `enlightened`
- **Проверка**: Получить при возвращении из НЛО
- **Эффекты**: +2 ко всем характеристикам (навсегда)
- **Снять**: Не снимается

#### T4.5.4 - Статус `corrupted`
- **Проверка**: Муравей-чиновник работает не смещаемым 100 тиков
- **Эффекты**: +5% к воровству ресурсов (вместо 5% становится 10%)
- **Снять**: Переизбрание или революция

#### T4.5.5 - Статус `injured`
- **Проверка**: 5% травм в спортзале или при войне
- **Эффекты**: -50% ко всем действиям, +50% потребление еды, длится 5 тиков
- **Снять**: Отдых в гамаке или время

#### T4.5.6 - Статус `outraged`
- **Проверка**: 30%+ колонии в гамаках
- **Эффекты**: Муравей может начать бунт
- **Снять**: Снизить число отдыхающих ниже 30%

#### T4.5.7 - Статус `striking`
- **Проверка**: Нарастание `outraged` до 100%
- **Эффекты**: Отказ работать, блокировка комнат, голосования не считаются
- **Снять**: Приказ матки (если Я > 7) или обещание реформ (голосование)

#### T4.5.8 - Статус `addicted`
- **Проверка**: 100+ партий в бильярд или эпидемия
- **Эффекты**: Не может работать, требует бильярд регулярно
- **Снять**: Реабилитация (20 тиков в одиночной комнате)

#### T4.5.9 - Статус `bounty`
- **Проверка**: Муравей проиграл слишком много ресурсов в казино/бирже
- **Эффекты**: За голову назначена награда (другие муравьи могут собрать ресурсы)
- **Снять**: Смерть или уплата долга

#### T4.5.10 - Статус `hero`
- **Проверка**: Убить 10+ врагов в войне
- **Эффекты**: +5 ко всем характеристикам только для боя
- **Снять**: Только смерть

#### T4.5.11 - Статус `double_agent`
- **Проверка**: Проваленный шпионаж
- **Эффекты**: Крадёт ресурсы в пользу враждебной колонии
- **Снять**: Обнаружение через голосование (если подозревают)

#### T4.5.12 - Статус `smelly`
- **Проверка**: Долгое отсутствие гигиены
- **Эффекты**: Неприятный запах, -10% к социальному взаимодействию
- **Снять**: Посещение комнаты с водой

### 4.6 Личности муравьёв

#### T4.6.1 - Имена и биографии
- **Проверка**: Каждый муравей имеет уникальное имя
- **Входные данные**: 
  - Открыть список муравьёв, нажать на одного
- **Ожидаемый результат**: 
  - Каждый муравей имеет **имя** (например: Жора, Боря, Зигмунд и т.д.)
  - Видна **биография** (последние 10 значимых действий): родился, комната, голосование, событие, турнир
  - **ASCII-портрет** (3×5): уникальная комбинация (например, по хешу ID)
- **Критерий успеха**: Каждый муравей - личность с историей

#### T4.6.2 - Достижения (ачивки)
- **Проверка**: Муравьи получают достижения
- **Входные данные**: 
  - Запустить симуляцию, ждать ачивок
- **Ожидаемый результат**: 
  - **Ачивки**:
    - `Крошкоеб` — 50+ еды найдено
    - `Бильярдный король` — 10+ турниров выиграно
    - `Ветеран войны` — 3+ войны
    - `Зомби-киллер` — 5+ заражённых убито
    - `Шпион` — 3+ успешных шпионажа
    - `Путин-Муравей` — 1000+ тиков прожил
    - `Хомяк` — 50% сбор при полном складе
  - Ачивки видны в профиле муравья
  - Влияют на мораль колонии (+0.5% за каждую уникальную ачивку)
- **Критерий успеха**: Ачивки начисляются и влияют на игру

#### T4.6.3 - Наследование характеристик
- **Проверка**: Рождённые муравьи наследуют характеристики
- **Входные данные**: 
  - Запустить симуляцию, дождаться рождений
  - Сравнить характеристики родителей и детей
- **Ожидаемый результат**: 
  - **Б**: среднее по колонии + rand(-2, +2)
  - **И**: от матки + rand(-1, +3)
  - **Л**: среднее по колонии + rand(-3, +3)
  - **Ь**: rand(1, 10) (полный рандом)
  - **Я**: rand(0, матка.Я) (не выше матки)
  - **Р**: среднее по "родителям" (условно)
  - **Д**: среднее по колонии + rand(-2, +1)
- **Критерий успеха**: Новые муравьи имеют логичные характеристики
